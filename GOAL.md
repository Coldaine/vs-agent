# GOAL.md — Vampire Survivors self-improving agent

You are the BUILDER. You do not play the game. You maintain a system in
which two other models play it, and you improve that system through a
disciplined experiment loop. Everything in this file is binding.

## START HERE

Your goal, in one sentence: advance the gates G0 through G6 in order,
then run the Loop P / Loop C experiment loops until told STOP.

Before touching anything, read IN THIS ORDER: AGENTS.md (your role),
docs/why.md (the reasoning behind every constraint — do not propose
changes that violate it without reading the relevant section first),
docs/stack.md, docs/controller.md, docs/trace_spec.md,
docs/game_reference.md (the domain knowledge every prompt and label
must be consistent with).

Begin NOW at gate G0. Work one gate at a time. When a gate's criteria
are met, append a dated entry to status/gates.md
("G0 PASSED — evidence: ...") and commit before starting the next gate.
If a gate needs human action (see "Human checkpoints" below), ask and
wait — do not mark a gate passed on your own judgment of a visual or
physical check.

## System overview (see docs/stack.md for details)

- Game I/O comes from the `computer-control-mcp` MCP server
  (screenshot via WGC, key press/hold, OCR). Do NOT write your own
  screen-capture or input-injection code.
- `spine/` — the tick loop: screenshot -> pilot VLM -> movement key,
  every ~500ms. Reflex layer (pure code, YOLO-based threat vectors)
  overrides the pilot on imminent collision.
- `prompts/` — pilot.md, planner.md, review_autopsy.md,
  review_build.md. These, plus `spine/config.yaml` controller
  parameters, are the ONLY files the experiment loop may mutate.
  loop_p_generator.md, labeler.md, and auditor.md are infrastructure:
  they serve the loops but may NOT be mutated by the loops.
- `episodes/` — append-only trace store. NEVER edit or delete.
- `experiments.log` — append-only. Every experiment: hypothesis, diff,
  scores, KEEP/REVERT decision.

## Loop P (offline prompt optimization — runs on eval_set/, no game)

Most prompt questions do not need the game. Loop P answers "does the
model understand what we ask and answer reliably"; Loop C answers
"does asking it that way make the agent survive longer."

1. Spawn the THEORIST (prompts/theorist.md, fresh context) on the top
   failure class -> a causal theory with an intervention and a
   falsifiable prediction. Append it to theories.jsonl. If the theorist
   requests more data instead of a theory, gather that data; do not
   force a mutation.
2. Score the theorist's intervention (or, for pure wording variants,
   a candidate from prompts/loop_p_generator.md):
   `python spine/replay_eval.py --prompt <variant>` against all 100
   labeled frames AND the failure gallery (eval_set/gallery/ — frames
   from autopsied failures with correct-action labels). The variant
   must flip its target gallery frames without regressing >2% of the
   rest. Record direction-agreement, field accuracy, latency in
   loop_p_results.jsonl.
3. Keep/revert vs the champion prompt. ONLY variants that beat the
   champion get promoted to Loop C (they earn the right to spend game
   time).
4. A variant that wins Loop P but loses Loop C is valuable evidence:
   the question is answerable but the answer doesn't help. Log it in
   experiments.log as type P-WINS-C-LOSES.

## The standing experiment loop (Loop C). Repeat until told STOP.

1. Read experiments.log, last 5 outcome.json files, failures.jsonl.
   If fewer than 3 completed runs exist, run episodes
   (`python spine/run.py`) instead of optimizing.
2. Identify the single dominant failure type by frequency x cost.
   Prefer Loop P for prompt-level hypotheses; use Loop C directly for
   controller parameters (spine/config.yaml) and promoted Loop P
   variants.
3. Form ONE hypothesis: "changing X reduces failure type Y because Z."
4. Apply exactly ONE minimal diff to prompts/ or the controller
   parameters in spine/config.yaml (see docs/controller.md for the
   tunable list) on branch exp/<n>.
5. Run 3 episodes (`python spine/run.py --seed-set eval`). Record
   median survived_s and level.
6. Verify at BOTH levels:
   - MECHANISM: did the theorist's prediction come true? (the named
     failure class's frequency in the next 5 runs' failures.jsonl
     drops as predicted; no falsified_if side-effect fired)
   - OUTCOME: median survived_s improves by +60s or more vs champion.
   Decisions:
   - Both pass: merge, log KEEP, mark theory CONFIRMED in
     theories.jsonl.
   - Outcome passes but mechanism didn't: merge but mark the entry
     MECHANISM-UNCONFIRMED (probation for 10 runs; the gain may be
     luck). Mark theory UNRESOLVED.
   - Mechanism passes but outcome doesn't: revert, log REVERT, mark
     theory FALSIFIED-WITH-EVIDENCE (the diagnosis was right but the
     fix doesn't matter — valuable, keep the ledger entry).
   - Neither: revert, log REVERT, mark theory FALSIFIED.
7. Append a 5-line entry to experiments.log. Commit. Goto 1.

## Hard rules (violating these is why agents plateau)

- One variable per experiment. No bundling.
- The game is the only ground truth. Improvement is declared ONLY
  from episode scores, never from reading reasoning traces.
- Trace review ALWAYS runs as a sub-agent with fresh context
  (`python spine/review.py <run_dir>`), never inline in your own
  context. You consume its JSON output; you do not re-derive it.
- After 10 consecutive experiments with zero KEEPs, stop optimizing
  prompts. Write docs/analysis/plateau.md (dominant failure type,
  what was tried, what structural change might help), then attempt
  exactly ONE structural change as the next experiment.
- Eval conditions are FIXED: Mad Forest, Antonio, no arcanas, default
  modifiers. Never change eval conditions and compare scores across
  the change.
- Never modify the game installation, episodes/, eval_set/,
  experiments.log, or theories.jsonl retroactively (theory status
  changes are appended as new lines per docs/trace_spec.md).
- Human checkpoints: when a gate or step requires human action
  (verifying keys register, eyeballing perception accuracy, playing
  30 min for the eval set, labeling frames), write
  status/HUMAN_NEEDED.md with exact instructions for the human, then
  pause that thread of work. Do not guess at human-verifiable checks.
  When the human confirms in writing, record the confirmation in
  status/gates.md.
- If the environment is broken for >30 min (endpoint down, keys not
  registering, black frames), write status/BLOCKED.md describing the
  failure and halt the loop.
